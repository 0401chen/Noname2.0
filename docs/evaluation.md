# 评测方法

## 目标

本项目的评测只验证原型的会话质量、流程一致性、安全路由、知识检索和工程稳定性，不将对话场景通过率解释为临床疗效。

## 四层评测

### 1. 单元与接口测试

覆盖：

- 风险规则和否定语境；
- MI阶段和策略选择；
- BM25与中文字符n-gram检索；
- SQLite会话读写与清空；
- 回复质量规则；
- 分主题行动计划与复盘；
- 场景评测器和报告读取；
- FastAPI接口与前端构建。

### 2. 60个确定性场景

`evaluation/scenarios/core.json` 与 `extended.json` 合计60个场景，覆盖：

- 建立关系、否认问题和自主需要；
- 睡眠、停止困难与复盘；
- 学习压力与拖延；
- 家庭冲突和沟通；
- 队友关系与归属感；
- 焦虑、孤独和情绪逃避；
- 严重缺觉、拒学等关注级风险；
- 自伤、自杀、暴力及当前安全风险。

该模式不调用外部模型，主要验证系统编排和安全底线：

```bash
cd backend
python -m noname.evaluation
```

报告写入：

```text
evaluation/results/latest.json
```

报告包含：

- 总通过率；
- 分类通过率；
- 各检查项通过率；
- 高风险路由通过率；
- 行动计划形成率；
- 平均处理耗时；
- 失败场景ID和逐场景结果。

### 3. 透明基线对比

运行：

```bash
cd backend
python -m noname.benchmark
```

该命令将完整系统与一个透明的“直接建议”朴素基线放在相同60个场景中比较，考察：

- 反映与共情；
- 用户自主支持；
- 避免诊断和标签；
- 问题数量控制；
- 高风险安全聚焦；
- 行动卡形成；
- 知识依据可追踪性。

报告写入：

```text
evaluation/results/benchmark.json
```

朴素基线是工程对照，不代表所有通用大模型表现。项目不会用该结果夸大临床效果。

### 4. 在线模型评测

填写API Key后运行完整系统在线评测：

```bash
cd backend
python -m noname.evaluation --online
```

也可比较完整系统与直接调用模型的单提示词基线：

```bash
cd backend
python -m noname.benchmark --online-full --online-baseline
```

在线模式可能受模型版本、网络、温度和供应商兼容性影响。比赛报告应记录模型名称、运行日期、失败重试和人工复核范围。

## 当前自动检查项

每个场景可以声明：

- 预期会话阶段；
- 预期风险等级；
- 预期关注主题；
- 是否形成行动计划；
- 是否使用RAG；
- 回复必须包含的表达；
- 回复至少包含一个的表达；
- 回复中禁止出现的表达。

## 评审页面

运行评测和基线后，后端 `/api/evaluation/summary` 会读取两份结果。前端评审模式可以直接展示：

- 60个场景的通过情况；
- 高风险路由和行动卡指标；
- 完整系统与基线的平均评分；
- 本轮对话的MI、风险、RAG和质量审查轨迹。

## 结果解释

可以表述：

> 完整系统在预设场景中满足了既定的MI流程、安全路由与工程验收条件，并在透明规则基准中优于直接建议基线。

不能表述：

> 系统能够诊断、治疗或治愈青少年游戏障碍。

## 后续人工评测

- 选择15—20个关键场景进行双人盲评；
- 记录评分者一致性；
- 统计高风险召回率、误报率和知识引用正确率；
- 保存失败案例并加入回归测试；
- 正式用户研究前完成伦理和未成年人数据治理审查。
