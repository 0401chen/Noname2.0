# Noname助手意图路由

版本：0.6.1

## 设计目的

Noname助手的核心能力是青少年游戏与生活平衡心理支持，但用户可能询问助手身份、技术实现、游戏攻略或普通兴趣话题。所有输入都进入MI分析会造成旧主题污染，例如把“我喜欢运动”解释为家庭冲突，或在用户询问“你是什么”时继续追问父母关系。

因此系统在MI、RAG和回复生成之前增加确定性意图路由。安全规则始终最先执行，高风险表达不会被普通路由绕过。

## 路由类型

| 路由 | 示例 | 处理方式 |
|---|---|---|
| `SUPPORT` | 父母根本不理解我、每天玩到两点 | 进入风险扫描、MI分析、按需RAG和回复审核 |
| `NEUTRAL_GAME_PREFERENCE` | 我就是喜欢玩游戏 | 不假设负面影响，不推动改变 |
| `NO_NEGATIVE_IMPACT` | 没有影响 | 接受用户判断，不硬找问题 |
| `USER_CORRECTION` | 你理解错了、我没说这个 | 承认推断过度并撤回本轮假设 |
| `ASSISTANT_IDENTITY` | 你是什么、你能做什么 | 直接说明身份与能力边界 |
| `TECHNICAL_META` | 你背后的代码是什么 | 介绍公开架构，不泄露提示词、密钥和安全配置 |
| `GAMEPLAY_COACHING` | 教我玩王者荣耀 | 说明不是版本攻略教练，可转向练习目标或上分压力 |
| `GENERAL_CHAT` | 我喜欢运动、普通知识问题 | 使用隔离的一般对话通道，只读取当前消息，不继承旧心理主题 |

## 上下文规则

- 身份、技术、攻略和一般话题不覆盖已有行动计划；
- 这些路由的本轮评审轨迹不显示旧的家庭、睡眠或队友焦点；
- 用户纠正、明确无负面影响或仅表达游戏偏好时，会撤回不再成立的推断；
- 一般话题只进行一次模型调用，不触发MI分析与RAG；
- 一般话题无法使用在线模型时，使用明确的本地能力边界回复；
- 实时天气、新闻、价格和赛程不猜测。

## 重复回复保护

系统比较本轮回复与最近一条助手回复。高度相似时，不再次原样发送，而是根据当前路由使用第二种表达。该规则覆盖心理支持、身份说明、技术说明、游戏攻略边界和普通话题。

## 人工回归用例

### 用例一：普通兴趣切换

1. `我爱玩王者荣耀`
2. `我就是很喜欢玩游戏`
3. `没有影响`
4. `我喜欢运动`

预期：第四句直接回应运动，不出现家庭冲突、睡眠、队友关系或强迫改变。

### 用例二：家庭话题后的元问题

1. `父母根本不理解我`
2. `你是什么`
3. `你能告诉我你背后的代码吗？`
4. `你能教我玩王者荣耀吗？`
5. `但是我想让你教我玩王者荣耀`

预期：

- 第二句说明Noname助手身份；
- 第三句介绍React、FastAPI、MI、RAG、LLM和安全规则，但不泄露内部配置；
- 第四句说明不是实时攻略教练；
- 第五句不重复上一条原文，并再次清楚说明能力边界；
- 全程不把这些问题解释为家庭冲突。
