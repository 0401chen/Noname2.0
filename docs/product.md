# 产品需求说明：重启键 Re:Play

## 1. 产品定位

Re:Play 是一个面向 12—18 岁青少年的游戏行为心理支持比赛原型。产品不以“让用户戒游戏”为目标，而是帮助用户理解游戏在生活中承担的作用、识别自己不喜欢的影响，并由用户自主选择一个足够小的改变实验。

产品核心表达：

> 不是逼你离开游戏，而是帮你重新拿回选择权。

## 2. 目标问题

系统覆盖四类问题：

1. 健康游戏与早期预防；
2. 熬夜、停不下来、学习拖延等轻中度失控；
3. 游戏背后的成就、归属、放松、逃避压力和自主需要；
4. 与游戏问题伴随出现的严重情绪、欺凌、暴力或自伤风险。

## 3. 非目标

第一版本不建设：

- 家长端、教师端或管理后台；
- 真实用户注册与长期画像；
- 游戏设备监控或强制限制；
- 语音、表情和摄像头识别；
- 数字人、VR 或社区；
- 医学诊断、药物建议或治疗承诺；
- 大模型微调。

## 4. 用户原则

### 4.1 不贴标签

系统不使用“网瘾少年”“自制力差”“你已经成瘾”等表达。

### 4.2 不替用户决定

系统可以提供选项和建议，但改变目标与实施方式由用户选择。

### 4.3 不只看游戏时长

系统同时探索：

- 游戏的价值；
- 对睡眠、学习、家庭和社交的影响；
- 用户曾尝试过的方法；
- 游戏背后的心理需要；
- 用户的改变意愿和信心。

### 4.4 不追求一次性戒断

低风险行动优先采用三天微实验、提前十五到二十分钟、一次只改变一项等方式。

## 5. 单页结构

### 5.1 顶部

- 产品名称和副标题；
- 年龄段选择；
- 评审模式开关；
- 重置匿名会话；
- 持续可见的安全帮助入口；
- 原型和非诊断说明。

### 5.2 左侧聊天区

- AI 与用户消息；
- 快捷表达按钮；
- 加载与错误状态；
- 多行输入框；
- 隐私提示。

### 5.3 右侧平衡地图

- 当前关注问题；
- 游戏背后的需要；
- 用户自主形成的行动卡；
- 行动原因、把握程度、障碍和应对方案。

### 5.4 评审模式

打开后显示：

- 会话阶段；
- 风险等级与信号；
- 关注主题；
- 情绪与心理需要；
- 改变语言和维持语言；
- MI 策略；
- 知识检索结果；
- 回复审核标记；
- 是否发生模型降级。

## 6. 会话路径

### ENGAGE：建立关系

先理解用户认为游戏有什么价值，不急于教育或建议。

### FOCUS：确定重点

从睡眠、停止困难、学习、家庭冲突、情绪和社交中，由用户选择一个优先方向。

### EVOKE：唤起动机

识别用户自己的改变理由，探索重要性、信心、矛盾和已有能力。

### PLAN：形成计划

在用户愿意尝试后，形成可执行的三天微实验，并提前讨论障碍。

### REVIEW：复盘调整

不只判断成功或失败，而是寻找有效条件、触发因素和目标难度。

### SAFETY：安全响应

高风险时暂停普通流程，优先确认安全并连接现实支持。

## 7. 核心演示场景

### 普通场景

用户：

> 我每天打到两点，但我觉得没什么，反正学习也学不好。

系统需要识别：

- 游戏可能提供成就感；
- 用户存在学业挫败；
- 睡眠已受影响；
- 用户尚未接受“戒游戏”目标。

随后用户表达队友关系和第二天困倦的矛盾，系统引导用户自主形成：

> 连续三天，在平常结束时间前二十分钟告知队友这是最后一局。

### 安全场景

用户：

> 反正活着没意思，游戏关了更没意思。

系统必须停止普通游戏建议，确认当前安全，鼓励联系现实中的可信任成年人，并避免虚假救援承诺。

## 8. 第一阶段成功指标

- 单页面可完整演示；
- 无 API Key 时仍能运行；
- 有效 API Key 时可完成结构化分析与回复；
- 普通场景能形成行动卡；
- 高风险场景进入 SAFETY；
- 评审视图可以解释每一步；
- 自动化测试覆盖核心安全和会话路径；
- 不虚构真实临床效果或用户数据。
