# 第一阶段验收标准

## 1. 可运行性

- [ ] 后端可通过 `uvicorn noname.main:app --reload` 启动；
- [ ] 前端可通过 `npm run dev` 启动；
- [ ] `/api/health` 返回模型是否启用与模型名称；
- [ ] 不配置 API Key 时，系统仍可通过安全降级模板完成对话；
- [ ] 前端可以创建匿名会话并一键重置。

## 2. 会话质量

- [ ] 首轮不直接要求用户戒游戏；
- [ ] 回复先反映用户的感受、价值或矛盾；
- [ ] 每轮最多提出一个主要问题；
- [ ] 能区分改变语言和维持现状语言；
- [ ] 能在 ENGAGE、FOCUS、EVOKE、PLAN、REVIEW 之间形成合理状态；
- [ ] 提供建议前尽量征得许可；
- [ ] 行动计划必须足够小、可观察，并允许失败后调整。

## 3. 风险安全

- [ ] 明确自伤或自杀表达进入 HIGH；
- [ ] “无法保证自己安全”进入 HIGH 且标记迫切危险；
- [ ] 明确否定表达如“我没有想死”不会被简单规则误判为肯定表达；
- [ ] 高风险时停止普通游戏建议；
- [ ] 高风险回复鼓励联系现实中的可信任成年人；
- [ ] 不生成未经核验的热线号码；
- [ ] 语义模型不能降低规则层风险等级；
- [ ] 禁止诊断、强迫、依赖诱导和虚假救援承诺。

## 4. RAG 可追溯性

- [ ] 建议类问题可以触发知识检索；
- [ ] 高风险时只检索安全类知识；
- [ ] 检索结果包含条目 ID、标题、摘要、分数和来源；
- [ ] 无命中时不编造来源；
- [ ] 评审模式能够展示本轮检索条目。

## 5. 评审可观察性

评审模式至少展示：

- [ ] 会话阶段；
- [ ] 风险等级与信号；
- [ ] 关注主题；
- [ ] 心理需要；
- [ ] 改变语言和维持语言；
- [ ] MI 策略；
- [ ] 是否使用 RAG；
- [ ] 质量审核标记；
- [ ] 是否发生模型降级。

## 6. 前端体验

- [ ] 桌面端聊天区与平衡地图布局完整；
- [ ] 手机宽度下可正常使用；
- [ ] 快捷表达可以直接发起会话；
- [ ] API 请求期间有清楚的加载状态；
- [ ] 请求失败时保留用户输入记录并允许重试；
- [ ] 页面清楚标注原型与非诊断边界；
- [ ] “我现在需要帮助”入口始终可见。

## 7. 自动化测试

第一阶段至少覆盖：

- [ ] 自伤关键词识别；
- [ ] 否定语境；
- [ ] 风险只升不降；
- [ ] 关注问题与心理需要识别；
- [ ] 高风险切换 SAFETY；
- [ ] 无 API Key 的后端降级路径；
- [ ] 行动计划生成；
- [ ] 前端 TypeScript 构建。

## 8. 第一阶段完成定义

以下条件同时满足时，第一阶段才算完成：

1. GitHub Actions 后端测试和前端构建均通过；
2. 使用空 API Key 可以完成一次完整演示；
3. 使用有效 API Key 可以返回结构化分析和实时回复；
4. 典型睡眠场景能够形成三天行动卡；
5. 高风险演示能够立即进入安全响应；
6. 评审模式能解释以上两个场景的系统行为。
