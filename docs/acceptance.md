# 最终比赛版本验收清单

状态说明：

- `[x]`：已实现；
- `[~]`：已实现，但仍建议在最终展示电脑再次确认；
- `[ ]`：后续研究或正式部署阶段工作。

本清单验证的是工程实现和比赛演示条件，不代表临床疗效。

## 1. 本地可运行性

- [x] Python 3.11 环境可以安装项目依赖；
- [x] 后端可以通过 `uvicorn noname.main:app --reload --host 127.0.0.1 --port 8000` 启动；
- [x] 前端可以通过 `npm run dev` 启动；
- [x] 前端使用 `/api/chat/stream` 与后端通信；
- [x] 有效 API Key 可以产生在线模型回复；
- [x] 匿名会话可以重新开始；
- [x] 前端保留非诊断和安全边界提示；
- [~] 最终展示前再次运行模型接口自检；
- [~] 最终展示前再次执行完整 Pytest 和前端生产构建。

## 2. 会话编排

- [x] 首轮不直接要求用户戒游戏；
- [x] 会话阶段支持 `ENGAGE / FOCUS / EVOKE / PLAN / REVIEW / SAFETY`；
- [x] 每轮生成结构化会话分析；
- [x] 区分当前 `focus` 与持久 `anchor`；
- [x] 连续支线探索后可以桥接回用户最初主线；
- [x] 支持改变语言和维持现状语言；
- [x] MI策略参与回复编排；
- [x] 限制连续机械追问和单轮问题数量；
- [x] 用户仅表达喜欢游戏时不会直接推断成瘾或强迫改变；
- [x] 用户改变意愿较低时优先使用自主支持。

## 3. 长期会话

- [x] 正常会话读取近期多轮原始消息；
- [x] 长对话达到阈值后支持滚动摘要；
- [x] 滚动摘要与近期原始消息共同提供上下文；
- [x] 主线锚点、行动计划和安全状态独立于摘要保存；
- [x] 摘要只保留用户明确表达和后续有用信息；
- [x] 摘要文本不能改变系统规则或安全边界。

## 4. 微行动规划

- [x] 只有用户表达行动意图或明确提出可执行行为时才创建计划；
- [x] 单纯询问“有没有什么办法”不会自动创建计划；
- [x] 支持提前结束、减少时长、时间边界、闹钟提醒等行动；
- [x] 支持“每局结束后暂停再决定是否继续”等自然策略；
- [x] 行动计划包含行为、持续时间、原因、障碍和应对方式；
- [x] 行动行为优先保留用户自己提出的内容；
- [x] 部分缺失字段可根据当前主题辅助补全；
- [x] 系统将计划定位为可调整的“小实验”，而不是强制戒断；
- [x] ActionPlan 保留后续复盘状态字段；
- [ ] 当前版本不是通用多任务自主规划器，不支持复杂任务依赖和多个并行计划。

## 5. 风险安全

- [x] 明确自伤、自杀、无法保证安全等表达进入 HIGH；
- [x] 高风险进入持续 `SAFETY` 状态；
- [x] 下一轮不重复危险关键词时仍保持安全模式；
- [x] 安全模式暂停普通游戏建议和行动计划；
- [x] 规则层风险不能被语义模型降低；
- [x] 支持结合上一轮问题理解“有 / 没有”等短回答；
- [x] 安全状态结构化记录是否独处、是否有人陪、是否联系支持等事实；
- [x] LLM 不能自行决定退出安全模式；
- [x] 退出 SAFETY 由程序化条件控制；
- [x] 不生成未经核验的热线号码；
- [x] 不承诺 AI 可以现实救援；
- [x] 高风险回复优先连接现实中的可信任成年人和紧急支持。

## 6. RAG

- [x] RAG 按需触发，不是每轮强制检索；
- [x] 当前采用 BM25 + 中文字符 n-gram 混合检索；
- [x] 检索结果保留 BM25 分数、语义相似度、命中词和来源；
- [x] 默认最多返回 4 条知识；
- [x] 高风险只检索安全类别知识；
- [x] 无命中时不伪造来源；
- [x] RAG 主要为回复和行动建议提供依据，不夸大为通用规划引擎。

## 7. 回复质量与降级

- [x] 检查诊断/标签化表达；
- [x] 检查强迫性语言；
- [x] 检查 AI 依赖诱导；
- [x] 检查虚假救援承诺；
- [x] 检查高风险下是否偏离安全主题；
- [x] 检查内部状态泄露；
- [x] 检查回复过长和问题过多；
- [x] 严重质量标记触发确定性 fallback；
- [x] 模型结构化输出失败时可以降级到规则分析。

## 8. 前端比赛体验

- [x] 桌面端聊天区可用；
- [x] 右侧展示“目前关注 / 我正在发现 / 我的小实验”；
- [x] 高风险时右侧切换为安全优先内容；
- [x] 用户消息和模型回复支持应用层流式展示；
- [x] 快捷回复可直接继续对话；
- [x] 请求失败保留页面上下文并提示重试；
- [x] 比赛版不直接展示内部 MI / RAG / 风险调试字段；
- [x] 开发者可以通过后端日志查看完整决策轨迹；
- [~] 最终展示电脑检查 100%、125%、150% 浏览器缩放；
- [~] 最终录屏前确认页面无旧缓存和测试数据。

## 9. 后端可观察性

- [x] 每轮输出 `TURN_STATE`；
- [x] 日志包含 `stage / risk / focus / anchor / strategies`；
- [x] 日志包含 `rag / hits / plan / fallback / quality`；
- [x] 日志包含模型分析与生成模式和处理耗时；
- [x] 高风险额外输出 `SAFETY_STATE`；
- [x] 长会话压缩时输出 `LONG_MEMORY`；
- [x] 状态日志不直接打印用户原文。

## 10. 自动化验证

最终提交前建议重新确认：

```bash
cd backend
pytest -q \
  tests/test_final_version.py \
  tests/test_service.py \
  tests/test_safety.py \
  tests/test_evaluation.py
```

前端：

```bash
cd frontend
npm run build
```

确定性场景：

```bash
cd backend
python -m noname.evaluation
```

如需基线：

```bash
python -m noname.benchmark
```

不要在材料中写“测试全部通过”，除非已经在最终代码和最终环境上实际重新运行并保存结果。

## 12. 当前项目边界

可以声称：

> 当前系统实现了 MI 驱动的状态化多轮会话、主线保持、按需混合RAG、长期滚动摘要、用户意图驱动的微行动实验和持续安全状态机，并通过自动化测试与场景评测验证工程流程。

不应声称：

> 已经通过临床验证、能够诊断游戏障碍、已经证明能降低成瘾率，或拥有通用自主规划能力。
